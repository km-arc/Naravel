# PDR-001: فلسفهٔ ناراول و قانون parity

- **وضعیت:** پذیرفته‌شده
- **معادل لاراول:** کل فریم‌ورک
- **معادل native دات‌نت:** BCL و `Microsoft.Extensions.*` (DI، Options، Configuration، Logging، Hosting)

## زمینه
هدف بازسازی قابلیت‌های لاراول در .NET است. پورت ساده‌لوحانه مکانیزم‌های PHP (متدهای magic، آرایه‌های بدون تایپ، reflection بر اساس قرارداد نام) را
کپی می‌کند که .NET به آن‌ها نیاز ندارد و نتیجه را غریبه و ضعیف‌تر می‌کند.

## تصمیم
۱. ویژگی لاراول را **فقط وقتی** پیاده کن که روی چیزی که .NET دارد **آورده** داشته باشد.
۲. اگر .NET آن را native و idiomatic حل می‌کند، از همان استفاده و مستند کن.
۳. *مفاهیم، واژگان و ساختار* لاراول حفظ شود تا توسعه‌دهندهٔ لاراول راحت باشد؛ *نقاط قوت* .NET (تایپ، async، DI، Options) برای پیاده‌سازی به کار رود.
۴. هر تصمیم adopt/adapt/reject **قبل از کد** به‌صورت PDR با گزینه‌های ردشده ثبت شود.
۵. همه‌چیز با تست و مستندات انگلیسی + فارسی تحویل شود.

## پیامدها
- برخی ویژگی‌های لاراول عمداً وجود نخواهند داشت (`laravel-parity.md`).
- نوشتن اولیهٔ بیشتر؛ بازکاری بسیار کمتر و نیت بسیار روشن‌تر برای مشارکت‌کنندگان و ایجنت‌های AI.

## گزینه‌های ردشده
- *پورت خط‌به‌خط:* APIهای غیر idiomatic و کد اضافی می‌سازد.
- *فقط ابزارهای native بدون ناراول:* واژگان و ساختار لاراول را که دلیل وجود پروژه است از دست می‌دهد.
