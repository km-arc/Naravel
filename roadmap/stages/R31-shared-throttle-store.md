Out of scope: sliding-window and token-bucket algorithms; per-user dynamic limits; a cross-instance maintenance-mode flag (the PDR leaves it undecided); a flag on `ICacheStore` that says whether a store is shared; changing how the client address is determined (forwarded headers stay native ASP.NET Core); any change to `IRateLimiter` or `MemoryLock`; version bumps, tags and NuGet publishing (the release is a separate owner step).
Decisions: PDR-024, PDR-009 (Routing needs only the ASP.NET Core framework reference), PDR-007a (`IRateLimiter` stays the tool for explicit attempt counters). The in-process store keeps `PartitionedRateLimiter` bit for bit and the existing throttle tests pass without edits. The shared store makes one `ICacheStore.IncrementAsync` call per request, takes no lock and uses no third-party dependency. Defaults: `StoreTimeout` 250 ms, `BreakerPeriod` 5 s, failure mode `DegradeToLocal`; both numbers are options, so tuning them later is not an API change.

## Tasks
- [ ] **R31.T01 — The seam:** add the public `IThrottleStore` (`ValueTask<ThrottleDecision> AttemptAsync(string partitionKey, int permitLimit, TimeSpan window, CancellationToken ct)`) and `ThrottleDecision` (`Allowed`, `Remaining`, `RetryAfter`) to Routing, move today's `PartitionedRateLimiter` logic behind an in-process `IThrottleStore` that is the default, and make `ThrottleMiddleware` call the store. Headers and the 429 response stay as they are. New public members are declared in `PublicAPI.Unshipped.txt`. **Accept:** the existing throttle tests in `tests/Naravel.Routing.Tests` pass without any edit; a new test proves the middleware uses a registered `IThrottleStore` and the same `X-RateLimit-*`, `Retry-After` and 429 body for an in-process store and for a test double.
- [ ] **R31.T02 — Failure handling:** add `ThrottleFailureMode { DegradeToLocal (default), FailClosed, FailOpen }` chosen per policy (an overload of `ConfigureThrottlePolicy`; the existing overload keeps working and means `DegradeToLocal`), a per-call `StoreTimeout` linked to the request token, one breaker per store (Closed, Open for `BreakerPeriod`, Half-open with a single probe, time from `TimeProvider`), the per-instance degraded limiter, 503 with `Retry-After` for `FailClosed`, a client abort that is not a failure, one warning per breaker opening, and the `naravel.routing.throttle` and `naravel.routing.throttle.store_failures` counters with bounded dimensions (policy, outcome; never the subject). **Accept:** every test named in the table of PDR-024 *Verification required → Failure handling* exists under that name and passes in CI, using a test double of `IThrottleStore` and a manual `TimeProvider` (no test waits for a real breaker period).
- [ ] **R31.T03 — The Cache adapter package:** add `src/Naravel.Routing.Cache` (working name from the PDR; the id is final unless the owner says otherwise before the first pack) with `AddNaravelSharedThrottle(storeName)`: an `IThrottleStore` over `ICacheStore.IncrementAsync(key, 1, window)` with key `throttle:{SHA-256 of the partition key}:{bucket}`, `bucket = floor(UtcNow / window)`, `Allowed = count <= limit`, `Remaining = limit - count`, `RetryAfter = window - (now mod window)`, resolved from the named cache store. It depends on Routing and Cache only, adds no third-party dependency and does not use `IRateLimiter`. The project carries `Description`, `PackageTags`, `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt`, its package page `docs/nuget/Naravel.Routing.Cache.md` and an entry in `Naravel.slnx`. **Accept:** `dotnet pack Naravel.slnx -c Release -o ./nupkgs-check` produces the package, and `check-package-metadata.py`, `check-package-readmes.py` and `consumer-smoke.py --local` pass on it in CI (the packed-package checks cover a new package without edits, D-78 and D-80); a dependency-direction check shows no reference from Routing to Cache.
- [ ] **R31.T04 — Store behaviour tests:** add `tests/Naravel.Routing.Cache.Tests`. One store contract runs on the in-process store, on the Cache adapter over the Memory store and, gated on `NARAVEL_TEST_REDIS`, over Redis. Two application hosts on Redis share one quota and a restarted host keeps it (the existing per-instance test with the expectation inverted); a burst of concurrent requests of one subject does not queue on a lock; the window boundary and the clock-aligned bucket are proven with a manual `TimeProvider`; a long or unusual partition key gives a key that is hashed and within the Memcached key rules; many distinct subjects over several short windows leave the Memory entry count falling after the windows expire (a real window of a few hundred milliseconds, because `MemoryCacheStore` reads the system clock). **Accept:** the named tests pass in CI; the Redis cases run in the provider job and show as skipped, never as passed, when `NARAVEL_TEST_REDIS` is not set.
- [ ] **R31.T05 — Benchmark:** add a benchmark of the in-process path (it must not regress against the numbers before T01) and of the shared path on Redis (the claim is one store call per request). **Accept:** the benchmark project builds in CI and the PR description states the measured numbers and where they were run, or says NOT RUN; the owner reviews them before merge.
- [ ] **R31.T06 — Docs and records:** update `docs/en/routing.md` ("Throttle behind more than one server": what the shared store does, the clock-aligned window and its 2x burst at a boundary, the failure modes with the recommendation to opt credential endpoints into `FailClosed`, that Memory is process-local, and that maintenance mode is still process-local), `docs/nuget/Naravel.Routing.md` and the new package page, the package table in `README.md`, `CHANGELOG.md` under `[Unreleased]`, `roadmap/PARITY-MATRIX.md` and `roadmap/BACKLOG.md`. **Accept:** the English docs match the implementation; `python3 roadmap/check.py` passes; the CI docs, link and consistency checks pass.
