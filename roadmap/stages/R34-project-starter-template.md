## Tasks
- [ ] **R34.T01 — The template package and its guards (PDR-025 D1, D2):** add `templates/Naravel.Templates/Naravel.Templates.csproj` (package type `Template`, no build output, no default items, no symbols package, its own copyright, tags (at least four), release notes and the icon rule of `check-package-metadata.py`), list it in `Naravel.slnx` under a `/templates/` folder, add `docs/nuget/Naravel.Templates.md` in the layout of the other package pages (absolute links only), and teach `check-package-versions.py` to skip the starter's csproj files and `check-package-readmes.py` to expect the template's README, each with a self-test case. **Accept:** in CI, `dotnet pack Naravel.slnx` produces `Naravel.Templates.<VersionPrefix>.nupkg` whose nuspec has package type `Template`; `check-package-readmes.py`, `check-package-metadata.py`, `check-tag-version.py` and `check-package-versions.py` pass on the pack output; the self-tests of the changed scripts pass.
- [ ] **R34.T02 — The default application (D3, D5, D6):** add the `naravel` project template under `templates/Naravel.Templates/content/`: `.template.config/template.json` (identity, short name `naravel`, `sourceName`), the tree of D3 for the default choices (memory cache, `log` mail, `file` queue under `storage/`, SQLite file under `storage/`), one `config/*.json` per module, `routes/web.cs` with the welcome page and `/up`, the examples under `app/`, a `README.md`, a `.gitignore`, and a `tests/` project that uses the fakes, including `Environment_variables_override_config_files`. The version of the `Naravel.*` references is written once. **Accept:** the unpacked nupkg lists the tree of D3; `<Compile Remove="tests/**" />` is in the application project; the generated README names where secrets go. The build and the run are proved by T03.
- [ ] **R34.T03 — The template smoke for the default application (D9 steps 1 to 4):** add `.github/scripts/template-smoke.py` (with `--self-test`) and a `template-smoke` job to `ci.yml`, in the `needs` of `ci-ok` and of `publish`. It installs the template from the packed `.nupkg`, generates the default application outside the repository against a `nuget.config` that maps `Naravel.*` to the packed directory, builds it, runs its tests, publishes it, starts the published app and checks `/up` and `/`. **Accept:** the job is green on the pull request and prints a line that names the version and the combination it proved; `check-publish-gates.py` passes; the generated tests, `Environment_variables_override_config_files` among them, pass; the publish output holds `config/*.json` and `resources/views/welcome.html`.
- [ ] **R34.T04 — Parameters, the matrix and the pins (D4, D8):** add the symbols `database`, `cache`, `queue`, `mail` and `no-tests` with conditional content in the csproj, `Program.cs`, `config/*.json` and the tests; add `.github/scripts/check-template-pins.py` (with `--self-test`) to the `pins` job; extend `template-smoke.py` so that every parameter value once, and a few combinations, restore, build and pass their tests. **Accept:** the matrix runs in CI and every entry passes; `check-template-pins.py` fails when the template's `Naravel.*` version differs from `VersionPrefix` or a test-package pin differs from `Directory.Packages.props`, and passes on the repository; the log lists the combinations that were built and states that only the default was started.
- [ ] **R34.T05 — Item templates (D7):** add `naravel-job`, `naravel-event`, `naravel-listener`, `naravel-mailable` and `naravel-controller`, and a smoke step that generates each into the default application and builds it. **Accept:** the step passes in CI for all five; `dotnet new naravel-job -n SendWelcome -o app/Jobs` in a generated application adds `app/Jobs/SendWelcome.cs` that compiles in the namespace of the project, or with `--namespace` if T05 had to choose that form, and the docs show the command that was proved.
- [ ] **R34.T06 — Docs, package smoke and records:** the `README.md` "Get started" shows `dotnet new install Naravel.Templates` and `dotnet new naravel -n Blog` and keeps the `dotnet new web` path as "add to an existing project"; `docs/en/getting-started.md` gets a "Create an app" section with the parameters and the registration table link; `docs/en/laravel-parity.md` gets the row for the starter and the generators; `CHANGELOG.md` gets an `[Unreleased]` line; `package-smoke.yml` gets the install, generate and build steps for a published version. **Accept:** `check-doc-names.py --strict`, `check-package-readmes.py` and `roadmap/check.py` pass; every command in the docs was run by `template-smoke.py` in T03 to T05 (the docs name no command that the smoke did not run).
