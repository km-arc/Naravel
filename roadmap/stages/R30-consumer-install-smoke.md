Out of scope: runtime code or public API; dependencies; version bumps, tags and NuGet publishing; making the smoke a merge gate or a publish gate (decide after it has run green on main and against the published 0.1.1; a candidate for a later stage); runs against real Redis, RabbitMQ, Kafka, Memcached or database servers (the `services` and `database` jobs own those); Native AOT (the `aot-smoke` workflow owns it); changing or republishing the immutable 0.1.0 and 0.1.1 packages.
Decisions: No new dependency. The runtime checks are the existing program of `samples/Naravel.AotSmoke`, which already compiles in every build and covers Cache, Events, Mail, Queue and its adapters, Encryption, Filesystem, Scheduling, Pagination and Database; the consumer restores it from packages instead of ProjectReference, so it cannot drift from the sample. The consumer lives outside the repository (so `Directory.Build.props` and central package management do not apply), uses a fresh global packages folder, and maps `Naravel.*` to the packed directory only. It starts report-only, like `evidence.yml`, because a gate that has never run is a risk to every pull request.
