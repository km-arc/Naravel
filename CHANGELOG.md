# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). All packages share one version (monorepo, lock-step).

## [Unreleased]

### Fixed
- CI: the NuGet `publish` job now waits for every job `ci-ok` requires, including the service image pins (it did not wait for `pins` or `changes` before), and for `ci-ok` itself. `.github/scripts/check-publish-gates.py` (run by the `pins` job) fails the build if the two `needs:` lists drift apart.
- CI: the image pin check now also reads `docker-compose.yml`, whose database images were floating (`mysql:8.4`, `postgres:17-alpine`, `mssql/server:2022-latest`) although it claims to match the CI job; they are now the exact versions CI uses.
- CI: the NuGet `publish` job now checks that the tag matches the version of every packed `.nupkg` (`.github/scripts/check-tag-version.py`) before the NuGet login, so a tag such as `v0.1.0-preview` can no longer publish `0.1.0` packages, or the reverse. The `pins` job self-tests the script on every pull request.

### Release notes (R17)
- Prepared contents for Naravel's first `0.1.0` release: database query builder, routing, queue, cache, filesystem, events, mail, notifications, encryption, pagination, broadcasting, scheduling and Redis, all intended to ship in lock-step. Hashing, session and auth-lite were declined in favour of native .NET (recipes in the docs). The release has not yet been tagged or published.
- All audit findings are closed; the release has no open `roadmap/AUDIT.md` rows.
- Pre-1.0 (`0.x`): breaking changes remain allowed when listed here (OD-09); revisit before `1.0.0`.

### Removed
- Docs: removed the orphan `docs/en/querybuilder.md` (no Persian twin, described APIs that do not exist). Use `docs/en/database.md` / `docs/fa/database.md`. Closes AUDIT D-57.

### Changed
- Evidence (report-only `evidence.yml`): recorded CI-runner benchmark baselines (`docs/en|fa/benchmarks.md`) and the first measured trim/AOT inventory (`docs/en|fa/trimming-aot.md`: 126 warnings in 18 packages, about nine in ten from reflection JSON serialisation). The expanded Native AOT smoke in [run 41196158945](https://github.com/km-arc/Naravel/actions/runs/41196158945) subsequently published and ran all 14 selected checks; ILC reported 28 distinct warnings, all attributed to Dapper in the reachable database path. These results do not certify every package or dependency; no package is declared trim-safe or AOT-compatible yet.
- Cache rate limiter: Memcached `IncrementAsync(key, by, ttl)` now passes the TTL to the fallback increment, so a counter that expires between the add and the increment is recreated with an expiry instead of becoming permanent (a subject rejected forever). Documented local versus distributed behaviour (Memory and `throttle` are per process), lock-timeout behaviour, and added a concurrency test.
- Queue.Database (PDR-023): `DatabaseJobEnqueuer.Enqueue(db, job)` adds a job to the caller's own `DbContext`, so it commits or rolls back with the business changes in one `SaveChanges` (no lost or phantom job); `AddTransactionalEnqueue()`. `Naravel.Queue` gains `IJobMessageFactory` (implemented by `JobDispatcher`). Unique jobs, chains and batches are not supported by it; no outbox yet for Redis, Kafka or RabbitMQ.
- JSON contains contract: documented which values `WhereJsonContains` accepts per engine (scalar types, `Guid`/`DateTime`/enum refused on SQLite and SQL Server, `null` rejected everywhere, typed vs text comparison) and added offline positive and negative tests (`JsonContainsContractTests`). No behaviour change.
- Query builder: published the per-dialect contract ([docs/en/database-dialects.md](docs/en/database-dialects.md), Persian twin) with the capability matrix, error contract and the "not run on" ledger; the Laravel-compatibility claim is limited to the tested subset. New offline hostile-input tests (`QueryHostileInputTests`) and an executed upsert key-semantics scenario (MySQL reacts to any unique key).
- XML documentation is complete for every public API under `src/`, and `CS1591` is an error there (AUDIT D-17 closed). The suppression remains only for tests and samples.
- Events.Queue: `AddQueuedEventListener` overloads take per-listener dispatch options (connection, queue, delay, attempts, priority) and source-generated `JsonTypeInfo<TEvent>` for trimming/AOT-safe payloads (AUDIT D-26 closed). The existing overload is unchanged.
- Kafka queue driver: `PopAsync` polls with a zero timeout and an async delay instead of a blocking 200 ms `Consume`, so an idle poll holds no thread and cancellation is prompt (AUDIT D-21 closed).
- Query builder pagination (R26, PDR-022): `Query.PaginateAsync`, `SimplePaginateAsync` and `CursorPaginateAsync` (dictionary and typed overloads) return the R16 `Paginated<T>`, `SimplePaginated<T>` and `CursorPaginated<T>`. `Naravel.Database` now references `Naravel.Pagination`, which shares its cursor format through `InternalsVisibleTo` (AUDIT D-68).
- Redis (R03, PDR-010): new package `Naravel.Redis` (`RedisManager`, `IRedisConnection`, `AddNaravelRedis`; `Redis:Default` and `Redis:Stores:<name>:ConnectionString`). `Naravel.Cache.Redis` and `Naravel.Queue.Redis` borrow their connection from it: a store takes `Connection` (a name) or, as before, `ConnectionString` (equal strings share one connection, so a store and its lock no longer open two). `RedisCacheStore` and `RedisLock` gain `ownsConnection = true`, `RedisQueueDriver` gains `ownsConnection = false` and `Dispose`; the connection the Redis queue driver used to open and never close is now disposed by the manager. `Naravel.Cache.Redis` and `Naravel.Queue.Redis` no longer reference StackExchange.Redis directly.
- Dependencies: every package raised to the latest stable version without a NuGet vulnerability or deprecation flag, including StackExchange.Redis 3.4.20 and AWSSDK.S3 4.0.104.6 (new majors). FluentAssertions stays on 7.x (8.x is commercially licensed) and xunit on 2.x (v3 is a migration). Details and the full list: AUDIT D-65.

### Changed
- **Breaking (pre-1.0), PDR-012a / D-29:** the Kafka queue driver no longer supports delayed delivery. `DelayFor`/`RunAt` on a Kafka store now throws `NotSupportedException`, and a worker retry on Kafka is delivered immediately without its `Backoff` (a warning is logged once per job type). Previously a delayed or backed-off record blocked every record behind it in the partition. New `IQueueDriver.SupportsDelayedDelivery` (default `true`). Records written earlier with a future `AvailableAt` are still honored. Use Redis, Database or RabbitMQ for delayed jobs; see "Kafka: no delayed delivery" in `docs/en|fa/queue.md`.
- `ICacheStore` adds `IncrementAsync(key, by, ttl)`; external custom stores must implement the TTL-aware atomic counter operation.
- `ConfigureQueueJobs()` now maps failed-job and batch tables and `QueueJobs` connection/trace columns; apply an EF migration after upgrading.
- Queue reservation fencing (AUDIT D-28): `QueuedMessage.ReservationId` is stamped on every Redis/File/Database `PopAsync`, and `AckAsync`/`ReleaseAsync`/`FailAsync` are no-ops once the reservation was reclaimed or re-taken. **Database users must add the nullable `QueueJobs.ReservationId varchar(64)` column (EF migration) before upgrading.** Envelopes without the field stay unfenced; Redis scripts take an extra `ARGV` token.
- Queue job middleware (PDR-012b, R08.T02): jobs can declare their own middleware with `IHasJobMiddleware` (runs inside the global `IJobMiddleware`), and middleware that does not call `next` must now call `JobContext.Release(delay)` (back to the queue, no attempt counted) or `JobContext.Skip()` (acknowledged, not run). **Breaking before 1.0:** a middleware that returns without `next` and without either call used to make the worker treat the job as successful; it now fails the job with an explanatory exception. New counter `naravel.queue.outcome` (tag `outcome` = `released`/`skipped`).
- `IQueueDriver.TryFailAsync` (default member): returns `false` when a fencing driver (Redis/File/Database) lost the reservation. The queue worker then removes its `IFailedJobStore` record and skips the `failed` handler, so a fenced-out worker no longer leaves a failed-job record for a job another worker owns (AUDIT D-28).
- Pre-1.0 Queue interfaces gained durable-store and batch operations. Custom `IFailedJobStore` and `IBatchRepository` implementations must add the new members; `SleepWhenEmpty` remains an alias for `Rest`.
- `RabbitMQ.Client` is centrally upgraded from 6.8.1 to 7.2.2; the provider now uses async connection/channel APIs.

### Fixed
- `Naravel.Queue.Kafka`: each queue now consumes in its own consumer group (`<groupId>-<queue>`). With one shared group, a new queue's consumer triggered an eager rebalance that waited for idle consumers of other queues to poll again, stalling delivery for minutes (broker log evidence in D-25). **Breaking (pre-1.0):** new group ids restart from the earliest retained offset; drain Kafka queues before upgrading.
- `Naravel.Queue.Redis`: atomically push, promote delayed work, reclaim reservations, reserve, ack, release and fail with Lua scripts.
- `Naravel.Queue.Kafka`: serialize consumer operations, commit only contiguous acknowledged offsets per partition, and prioritize up to 256 records already available in a poll batch.
- `Naravel.Queue.RabbitMQ`: honor queue message priority using broker priority queues. Existing ready queues created without `x-max-priority` must be recreated before upgrade.
- `Naravel.Queue`: replace assembly-qualified job type resolution with an explicit alias registry, reject unknown/non-job payload types before deserialization, and deserialize at most once per attempt. This changes the queue wire identifier; worker-only processes must register their jobs, and legacy payloads need an explicit compatibility alias.
- `Naravel.Queue`: preserve the original connection, queue, priority, and max-attempt setting through static and runtime chain continuation; add optional source-generated JSON metadata.
- Cache tag reads/writes use a stable version zero until the first invalidation, preventing concurrent first-use requests from writing under divergent versions.
- Named Memory stores now default to store-name prefixes; Memcached null TTL means no expiry. Memcached server lists are validated because the provider shares one pooled client across named stores.
